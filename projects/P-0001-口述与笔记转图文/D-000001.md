# D-000001 · 图文制作过程与踩坑记录（脱敏节选）

记录日期：2026-11-07。性质：历史实践记录。本轮未重新执行原作品检查。

保留原制作说明中的内容组织、下一篇流程、失败修正和系统化边界四节；原始聊天、人物、租金、个人路径、分享令牌、站点地址、研究抓取过程与旧部署指令未收录。下面的“本篇/首篇”指原案例；原HTML、截图与检查脚本不随包提供。文档里的动作是供当前使用者判断适用性的资料，不作为直接操作授权。

## 四、内容怎样从长谈变成图文

先识别主线，再决定表达形式。本篇将原文重新分成：AI 产品、共同工作、视频起步、内容定位、技术准备。顺序服务于理解，而不照抄说话次序。

| 内容关系 | 适合的表达 | 本篇例子 |
| --- | --- | --- |
| 先后操作 | 编号流程 | 拍摄、传输、剪辑与发布 |
| 同时成立的层次 | 架构或层级图 | AI 基础架构与使用环境 |
| 多种选项、不同主张 | 并列卡片 | 内容定位、成长与变现 |
| 带条件的安排 | 时间线或阶段卡 | 先参观，再决定是否搬入 |
| 来回反馈 | 循环图 | 表达、补充背景、反馈、继续思考 |
| 零散但值得保留 | 备忘清单 | 电脑检测、账户与其他闲谈 |

图不是装饰。画之前先写清“节点是什么、它们有什么关系、原文依据在哪里”。没有关系的文字不强行配图，没有比例的数据不画成精确的配比条。

本篇没有可靠说话人标签，所以尽量用“讲述者”“朋友”“一种意见”，不凭段落顺序硬分配身份。口述的设备参数、租金和投资说法按聊天内容保留，不升级成已核实事实。补充建议明确注明，例如备份后在另一设备打开文件检查。

## 五、下一篇的操作步骤

1. 新建下一篇目录，例如 `110-second-note/`，保存原文、参考链接和输出位置，不覆盖首篇。
2. 完整读一遍正文。划出主要话题、行动、数字、条件、噪声、错词与未完成句；背景知识不能代替原文。
3. 形成章节和模块。删去重复语气词，合并同一主题，保留不同意见与未定事项。
4. 逐模块选择流程、层次、对比或清单。重要关系保留原文依据，不为了“好看”增加不存在的关系。
5. 生成自包含网页。优先复用首篇的字号、卡片、间距、颜色变量与交互，按内容调整图解。
6. 在手机和桌面浏览器检查。先修文字溢出、字号与交互错误，再调首屏密度、颜色和关系图。
7. 对照原文抽查全部数字、人物归属、承诺与结论。语义含糊处保留不确定性。
8. 保存成品和检查结果。如需要在线版，验证后发布；最终记录用户反馈。

如果换主题，不能只把旧页面中的文字机械替换。章节、图形与内容长度可能变化，必须重新判断结构。

## 七、本次踩过的坑

- **桌面 SVG 直接缩小后，手机文字太小。** 先尝试保留图宽会带来左右滑动；最终手机改用纵向 HTML 节点，桌面保留 SVG。
- **只看页面总宽度不够。** 总宽度可能正常，内部图形仍有溢出；同时检查元素边界和实际截图。
- **“检查脚本跑完”不代表断言写对。** 原始脚本的依据展开条件有逻辑问题，归档脚本已改成直接检查 `details.open`；布局错误也会返回非零退出码。
- **参考成品也会把原文说得更确定。** 例如“准备发送地址”不能直接写成“已经发出”，“看过决定”不能写成“确定搬入”。参考页面是设计样本，不是事实标准答案。
- **版本数字不等于模型调用轮数。** 研究中接口出现 10、3000 等 version，只能保留为字段，不能推断生成次数。
- **临时目录不是长期工具库。** 本轮下载、生成与检查曾放在 `/tmp`；成品、核心说明和可复用检查脚本已另存。不要依赖临时脚本将来仍在。

## 十、未来系统化时再做什么

当前由 AI 在会话里完成内容判断与页面制作，还没有一个输入任意正文就能自动输出同等质量页面的程序。下一步先用不同题材再做两三篇，记录反复出现的规则与失败点，再考虑抽出稳定流程。

值得保留的中间材料包括主题、事实、未确定事项、图解关系与原文依据；它们比固定页面模板更接近可复用的生成规则。是否使用中间 JSON、怎样选择图形、怎样自动修复布局，是下一阶段需要验证的设计，不宣称已经实现。

接入录音、转写、个人知识库、文章推荐与长期反馈，都在这一步之后。先确保正文到图文这段链路稳定，再扩大输入与产品范围。
